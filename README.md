# graph-traversal-algorithm
A graph traversal algorithm that tries to make use of as many previous calculations as it can using relative distances.
So, this is an attempt of making a graph traversing algorithm of my own. I am a first year student, currently into 3 months into programming. I have done python till just before OOP and java also still that level and some DSA in which i did standard sorting and search algorithms and I like to solve interesting questions and study some algorithms and making projects. This was one such attempt of solving LeetCode question 935, knight dialer. Through which I learnt about dynamic programming and tried making an algorithm to traverse the graph differently, not just reduce the number of iterations or loops. 
How this works is basically, when i start exploring a branch, i store a history of that current branch as i use DFS for exploring the branch. And i also keep a matrix where co-ordinates are (position, number of moves left) like in tabulation, and this is where i update the values as i find more paths. So, as i go down a branch and explore more positions below, i update the previous positions that came before it, so, lets say 6 was the first position with N moves left and then came 4, then in our matrix, [6][1] will be increased by one, so basically, how many paths there will be from position 6 if 1 move is left. Then came 9 after 4, [6][2] will be incremented, so its kinda like relative distance.
this whole portion is sorted.
Now, what if a position comes again, it can very well mess up the whole thing, for example, position 3 comes at 5 moves left and then at 2 moves left, now, the 3 at 5 moves left will also affect (3,0),(3,1),(3,2) and 3 at 2 moves left will also affect these, so what i do is, i set a boundary. I make every element in history list a list as well with 2 elements where first one is the position and second one is the moves of that position when it appears after it and at default it is -1, position one is also -1 at default, meaning no value is stored and its empty. lets say, 3 came at 7 moves left, then at 5 moves left and again at 3 moves left. so, in history, they will be stored like this [3,5],[3,3],[3,-1]...this is so that i can set a boundary on how many elements in that matrix they can affect. if the relative distance is greater than the 2nd element, only then they can affect.
